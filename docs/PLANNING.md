## Interview sequence

- [ ] First 30 minutes: discovery, usefulness, teaching and first adaptation.
- [ ] DNA: specimen acquisition, completion, bank ownership, sharing and anti-grind rules.
- [ ] Equipment: usage progression, directed mutation, branches, compatibility and recovery.
- [ ] Construction: reusable parts, structure constraints and meaningful alternate layouts.
- [ ] Ecology/economy: assimilation, biomass, containment, cleanup and renewable inputs.
- [ ] Logistics/transit: 3D terrain, junctions, cross-dimensional endpoints and costs.
- [ ] Dimension roles: ongoing Overworld, Nether and End operations, not one-time gates.
- [ ] Threats/helpers/bosses: approved first-release scope and hard performance budgets.
- [ ] Endgame/replayability: capability gains that preserve choices; campaign-length target.
- [ ] Initial content ontology, canonical names, registry IDs and data ownership.

## Before the first playable slice

- [ ] Approve exact acceptance criteria and scope, not just milestone names.
- [ ] Finalize the feature dependency matrix and presence/absence checks.
- [ ] Establish save versioning, resource conservation and ownership contracts.
- [ ] Add automated client startup/shutdown and isolated fixture/capture infrastructure.
- [ ] Approve first visual language and human-owned screenshot goldens.
- [ ] Implement data generation, resource freshness and recipe/advancement discovery checks.
- [ ] Establish UI foundation before any gameplay screens.
- [ ] Harden ktask so completion independently runs the authoritative verifier.
- [ ] Choose executor/models by task risk and demonstrated gate quality.
- [ ] Approve structured implementation tasks; do not queue ambiguous product design.

Proposed eras—not committed milestones: discovery → local adaptation → compositional
colony → sustained Nether operations → inter-colony transit → sustained End ecology
→ open-ended specialization. Discuss dependencies and playable exit criteria first.
