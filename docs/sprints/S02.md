# Sprint S02: feed a living workshop

Milestone: M2, first slice. Status: running; S01 is closed.

Goal: the player grows the first workshop from Spore Culture: an Organ Bud, a Digestive Sac that makes biomass, a Biomass Bladder that stores it, a Culture Bowl with a screen that grows cultures, a probe to talk to organs, the first achievements and the guide pages for all of it.

Acceptance (ROADMAP.md, M2 part): fresh Survival acquisition and recipe reveal, empty/full inventory, insufficient biomass, break/reload preserving one organ history. The rest of M2 (rack, loom, cradle, one awakened piece) is S03.

The planner did IF-009 to IF-011 as the pattern every organ copies. Sonnet does the rest, one story per run. The sprint is done only when its art stories in ART.md are accepted. Rules: [AGENTS.md](../../AGENTS.md). Template and loop: [ENGINEERING.md](../../ENGINEERING.md#stories-and-sprints).

Shared facts for every story here:

- Core (`core/`, no Minecraft): `foundation.Biomass` (int BU, checked, `ZERO`, `BUCKET` = 1000), `foundation.Refusal(key)`, `foundation.Outcome<T>` (sealed: `Done(value)`, `Refused(refusal)`), `foundation.TickQuota`, `foundation.WindowQuota`, `storage.BiomassTank(stored, reserved, capacity)` with `fill`, `drain`, `reserve`, `commit`, `release`, `room`, `processing.Batch(recipe, ticksRequired, ticksDone)` with `start`, `advance`, `isDone`, `percent`, `organ.OrganHistory(completedBatches)`.
- UI (`ui/`): `Bounds` (now with `bottomSlice`), `Meter(value, max)` with `filled(extent)` and `fillFromBottom(Bounds)`.
- Mod-side shared code: `foundation.Refusals.show(player, refusal)` shows `infestusfrontier.refusal.<key>` above the hotbar; `foundation.Persistence.read/write(MapCodec, tag)`: a block entity that cannot read its saved tag keeps it in `unreadable`, writes it back unchanged and refuses commands with `Persistence.CORRUPT`.
- Modules: `storage` (`StorageModule.BIOMASS_BLADDER`, `BIOMASS_BLADDER_ITEM`, `BIOMASS_BUCKET`, `BIOMASS_BLADDER_MENU`, data component `TANK` = `infestusfrontier:biomass_tank`), `processing` (`ProcessingModule.DIGESTIVE_SAC`, `DIGESTIVE_SAC_ITEM`, recipe type `DIGESTION` = `infestusfrontier:digestion`, `DIGESTION_SERIALIZER`), `organ` (`OrganModule.HISTORY` = `infestusfrontier:organ_history`; `organ.api.Organs.FOUNDATIONS` = block tag `infestusfrontier:organ_foundations`, `Organs.hasFoundation(level, pos)`), `discovery` (`DiscoveryModule.MAIN` creative tab; every new item is added to its `displayItems`).
- Biomass is the NeoForge fluid `infestusfrontier:biomass` (`StorageModule.BIOMASS`, `FLOWING_BIOMASS`, `BIOMASS_BLOCK`, `BIOMASS_BUCKET` is a vanilla `BucketItem`). One BU is one mB. Storage api: `BiomassHandler` (`tank`, `insert(amount, simulate)`, `extract(amount, simulate)`), `BiomassCapabilities.BLOCK` (the snapshot with reservations), `BiomassCodecs.BIOMASS` and `TANK` codecs, `BiomassFluids.handler(store)` (the `IFluidHandler` every organ registers as `Capabilities.FluidHandler.BLOCK`, so buckets and pipes work), `BiomassFluids.useOn(stack, level, pos, face, player, hand)`: every organ block calls it first in `useItemOn`; it runs `FluidUtil.interactWithFluidHandler` and shows the refusal (`storage.full`, `storage.empty`, `storage.wrong_fluid`). No transfer quota: buckets are vanilla.
- The organ pattern is `processing/DigestiveSacBlock.java` and `DigestiveSacBlockEntity.java`. Copy it: `BaseEntityBlock` with `simpleCodec`; `getStateForPlacement` returns null without `Organs.hasFoundation`; the block entity holds immutable core records, one `MapCodec` `SAVED`, `Persistence.read/write`, `unreadable`; `collectImplicitComponents`/`applyImplicitComponents`/`removeComponentsFromTag` carry state on the item, and the loot table uses `minecraft:copy_components` from `block_entity` with an `include` list; the server ticker returns at once when idle or when `hasFoundation` is false; empty hands act only when the offhand is empty too, otherwise `PASS`; unrelated items return `PASS_TO_DEFAULT_BLOCK_INTERACTION` so building against the organ works.
- Refusal keys are `<owner>.<condition>` and every new key gets a line in `assets/infestusfrontier/lang/en_us.json`. Status lines are `infestusfrontier.status.<organ>.<state>`.
- Placeholder textures: a flat two-tone PNG at the shipped size (64 block, 32 item), drawn with a five-line Pillow script that is not committed. Models are vanilla `cube_all`, `cube_column` or `item/generated`. Final art comes from ART.md. The Sac and the Bladder already have GeckoLib models (`art/gen_digestive_sac.py`, `art/gen_biomass_bladder.py`); a new organ gets its model from the planner after its platform story, never from the worker.
- Screens extend `foundation.screen.OrganScreen` (ENGINEERING.md, Architecture), which draws the panel, the status line and the biomass tank; a subclass returns a `Status(StatusKind, Component)` and adds parts along a `PartRow`: `new Well(row, slot, label)`, `new Vein(row, percentSupplier)`, `button(row, text, onPress)`. A screen never draws. `DigestiveSacScreen` and `BiomassBladderScreen` are the pattern. Every organ with state opens its screen on an empty hand (`ServerPlayer.openMenu`), and every screen gets a `demo.json` view with `"use": [x, y, z]` so the gate photographs it. The Sac's feed slot is an `ItemStackHandler` on the block entity, exposed as `Capabilities.ItemHandler.BLOCK`, so hoppers and pipes feed it; the Sac takes one item from it whenever idle.
- GameTests: one class per owner in `src/testMod/java/org/jd/infestusfrontier/testmod/`, template `infestusfrontier_tests:empty`, helpers `EcologyTests.holding`, `EcologyTests.use`, `ProcessingTests.handler(h, pos)`, `ProcessingTests.feedRepeatedly`. A mock player cannot open a screen: test menus through the block entity's `MenuProvider.createMenu` as `StorageTests.menuReadsTheLiveBalanceAndABlockInHandBuilds` does. For advancements use a `ServerPlayer` built directly, `new ServerPlayer(server, level, new GameProfile(UUID.randomUUID(), name), ClientInformation.createDefault())`, never placed in the level: `makeMockServerPlayerInLevel` trips Modonomicon's sync payload and `FakePlayer` advancements are no-ops. `DiscoveryTests.substrateAdvancementGrantedOnConversion` is the pattern; one such player per test, never in a loop. Batches need `timeoutTicks` on the `@GameTest`.
- Demo world rows (ENGINEERING.md, Demo world). Row A x taken: 0, 2, 4 (substrate), 12, 14 (IF-003), 16 (IF-006), 20 Digestive Sac, 22 Biomass Bladder, 24 Organ Bud, 26 Culture Bowl (IF-014). Signs stand at x+1 on z=-37, except the Craft sign at 11. Free from 28 east. Views: `start`, `inventory`, `hosts`, `patches`, `craft` (14.5), `workshop` (22.5, frames x 19..25), `bowl` (26.5, frames x 23..29), `sac_screen`, `bladder_screen`. A view frames about seven blocks of row A; an exhibit east of 28 needs a new view. The hotbar is full (eight `give`s plus the book): new demo items go to the main inventory with `item replace entity @s inventory.<n> with <item> <count>`, so an empty hotbar slot stays for the empty-hand screen views.
